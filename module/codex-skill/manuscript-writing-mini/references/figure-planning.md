# 图简报
默认 templates/figure_brief.yaml（brief_schema: compact-v1）用于单面板图：问题/主张、所用数据与来源、表现内容、类型、预期输出和可编辑来源、图注。
保留面板的科学作用、准确内容、sources、axes_variables（注明单位或解释不适用）和 visual_form。统计图在这些字段写清样本、误差/检验含义；不能因简报短而省略影响解释的信息。
多面板或 MIXED_MULTI_PANEL 必须使用 templates/figure_brief_full.yaml（无 schema 或 full），按原字段展开；多来源、机制推断或复杂统计也应选完整简报。
调用 nature-figure 时按它需要补充尺寸、来源和渲染验收，不复制引擎手册。实际资产仍需 manifest、哈希、图注、权限及原文核验。

## 视觉基准与示意图核查

已有用户认可的图时，将其路径和认可要点记入项目约定或图简报，后续同类图保持相当的构图层次、必要细节、标注清晰度和完成度；恢复任务时沿用，无需重复询问。没有认可范例且视觉方向尚不明确时，优先完成一张代表图供反馈，再批量展开同类图；用户已授权自主决定时可按既定目标继续。精美不等于元素多：不为复杂而堆叠装饰，不把某项目的复杂示意图风格强加给统计图。

示意图简报须明确对象如何连接、观测或作用方向、坐标/投影关系、信号到物理量的转换条件，以及哪些内容是示意、哪些来自测量。只核查适用于该图的关系。交付前既检查实际输出的版面，也检查物理/几何自洽与正文一致性；坐标可计算时核对关键点、线和方向，不能仅凭“看起来合理”。发现问题直接修正必要部分，避免借审图重做无关章节。

## 投稿输出与修改副本

将项目已约定的工具、导出格式和编辑性要求传给 nature-figure。按图的科学内容选择制作方式；确有必要时可结合矢量编辑或三维建模等工具，保留源文件并完成相同的科学与输出核查，不为视觉炫技更换工具。遵守用户已有后端选择，不擅自安装软件或改变其明确约束。

若PPT等只是方便作者修改的副本，以正式投稿图的清晰度和科学表达为先，不为全元素原生可编辑降低正式图质量。文字和常改元素尽量可编辑，复杂内容可保留为独立矢量或高清组件，并说明编辑范围；不得将整图截图称为全元素可编辑。若用户明确要求全元素原生可编辑，则按该要求制作，必要时说明表现取舍。

同步修订各交付格式、图注和来源记录；投稿版按实际使用尺寸检查，修改版另查内容一致性与实际编辑能力。绘图后端、PPT等具体格式及审美偏好留在项目层，不设为所有项目的固定要求。
